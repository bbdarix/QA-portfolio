
# Test Plan — SauceDemo

**Project:** SauceDemo (Swag Labs)  
**Application URL:** https://www.saucedemo.com/  
**Testing Type:** Manual Functional Testing  
**Test Environment:** Web Browser  
**Status:** In Progress

## 1. Objective

The objective of this project is to verify the core functionality of the SauceDemo e-commerce application and identify potential defects affecting the user experience.

## 2. Scope of Testing

### In Scope

- User authentication (valid and invalid credentials)
- Product listing and product details
- Product sorting
- Adding and removing products from the shopping cart
- Shopping cart functionality
- Checkout form validation
- Order completion
- Navigation and logout

### Out of Scope

- Payment gateway integration
- Backend database testing
- Performance and load testing
- Security penetration testing
- Mobile application testing

## 3. Testing Approach

Manual testing will be performed using the following techniques:

- Positive testing
- Negative testing
- Equivalence partitioning
- Boundary value analysis
- Exploratory testing
- Regression testing of affected functionality when applicable

Test cases will be documented and executed manually. Actual results will be compared with expected results.

## 4. Test Environment

- Application: SauceDemo
- Platform: Web
- Browser: Google Chrome
- Operating System: Windows
- Test Account: standard_user
- Password: Test credentials provided on the SauceDemo login page

## 5. Test Deliverables

- Test Plan
- Test Checklist
- Test Cases
- Test Execution Results
- Bug Reports (if defects are found)
- Test Summary Report

## 6. Entry Criteria

- The application is accessible.
- Test credentials are available.
- Core application functionality can be accessed.
- The test scope is defined.

## 7. Exit Criteria

- All planned test cases have been executed.
- Test execution results have been documented.
- Any identified defects have been recorded.
- A Test Summary Report has been prepared.

## 8. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Demo application unavailable | Testing is blocked | Resume testing when available |
| Application changes during testing | Expected results may become outdated | Review and update test cases |
| Limited access to backend systems | Some scenarios cannot be verified | Focus on observable UI behavior |

## 9. Test Execution Status

Not Started

## 10. Conclusion

The final testing results, identified defects, and overall assessment will be documented in the Test Summary Report after test execution.
